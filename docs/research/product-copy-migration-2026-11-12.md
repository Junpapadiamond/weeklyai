# Targeted product copy migration, 2026-11-12

Production reads MongoDB, so editing the JSON catalog alone does not replace existing database text. The reviewed manifest at `crawler/data/migrations/product_copy_focus_2026_11_12.json` contains seven logical products and 22 changed text fields, with exact before/after values from `c52717a` and `e144857`. Only `description`, `description_en`, `why_matters` and `why_matters_en` are eligible. Website, identity, funding, score, logos, and all other fields remain intact.

Harvey has an explicitly declared historical record, `harveyllc.com`, alongside the catalog identity `harvey.ai/blog`. Its four older English text values were checked through the production API and are fixed in the manifest; they are not learned automatically during migration. Either identity may exist, or both. All present declared copies are checked and updated to the same reviewed copy, preventing later deduplication or merging from restoring the older financing-led text. Both copies would produce eight physical records and 26 field changes across the same seven logical products.

The script requires at least one existing declared record per product. An undeclared identity with the same product name, a duplicate declared identity, a name mismatch, a missing text field, or any text outside that record's exact before/after values fails the whole preflight before any write. It never upserts. After preflight, each update compares the record identity and every observed approved text field before setting only changed text fields. A concurrent edit stops further updates without overwriting it; earlier successful writes can remain and are recorded in the receipt.

The workflow runs on a main-branch push touching this manifest or migration script and shares the `daily-data-update` concurrency group. It uses the existing `MONGO_URI` secret and `MONGO_DB_NAME` variable without logging them. Its successful-preflight receipt contains the complete reviewed manifest plus per-record observed/target values and execution status; keep it for inspection or rollback.

A failed preflight instead saves a diagnostic receipt containing only declared product names/keys, raw values of the four allowed text fields, and their missing-field names. It excludes MongoDB IDs, all other product data, and connection settings. Logs identify the conflicting field without printing its text. This diagnostic does not authorize additional before values or missing fields; any manifest amendment requires review of the raw evidence.

Run `python crawler/tools/migrate_product_copy.py --dry-run --receipt product-copy-preflight.json` to preflight only, or omit `--dry-run` to apply. To restore each declared record's own old text, use `--rollback --manifest product-copy-migration-receipt.json --receipt product-copy-rollback.json` with the saved forward receipt. Rollback applies the same strict preflight and compare-and-set checks. The script reads its connection from the environment; no credentials belong in the command or manifest.
